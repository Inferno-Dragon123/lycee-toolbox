# 卡组检索升级

本功能先在 `codex/search-filters` 预览分支实现，于 2026-10-04 通过用户人工审核，纳入 `master` 正式发布。预览分支保留供后续试验；生产数据库需单独执行下述迁移和构成索引补建。

## 使用规则

- 原推荐整合为常驻的「卡组检索」。卡牌旁的「加入检索」或批量卡号输入可选择最多 10 种基础编号；异画去重，支持全部包含／任意包含。
- 来源、卡组类型、系列单会社、属性构成、属性数量范围及所选卡牌可组合。同一多选内为任一匹配，不同筛选项同时满足。
- 卡组类型多选为系列单／混成。系列单会社可选择多个符号，例如 NAV、AL；此条件仅匹配符合这些会社资格的系列单，与类型条件同时生效。未选表示不限。
- 属性多选表示任一所选分类至少 1 张。雪、月、花、宙、日、他分别可设上下限，允许只填一端，0 有效，范围为 0～200。纯花可以用花下限 60，或其他属性上限 0 进一步限制。
- 修改条件后点击「检索」应用；上下页、跳页、末页及刷新结果沿用已应用条件。清空条件重新查询所有当前模式卡组；我的上传与管理员模式继续遵循原权限。
- 「已选筛选条件」栏汇总当前来源、类型、会社、属性、数量范围、卡号和匹配方式；点击条件旁的 × 单独移除，再点击「检索」应用。默认「全部包含」作为匹配说明展示；移除「任意包含」会恢复默认方式。待检索时会明确说明当前结果仍沿用上次条件。
- 官网卡组的名称链接在新窗口打开官网原卡组；本站投稿的名称链接继续打开本站预览。每套卡组保留「预览」「导入卡组」按钮，取消重复的独立官网链接。
- 每页 20 套，显示匹配总量及总页数。越界页码提示修正，加载和空结果禁用分页；服务端对已有结果的越界请求返回当前最后一页，避免列表变化导致空白页。

## 数据来源

`lib/deck-composition.js` 以实际数量和完整卡号计算构成。某些联动卡有多个会社资格（例如 `SP VA`）；全副卡牌会社资格的交集非空才是系列单，不能将不同发行版本简单视为混成。缺少资料时保守标为「系列资料不足」。这不是比赛合法性审核。

官网列表链接下方的完整 `[MIX]`／`[NIT]` 等标签及六项张数优先保存。官网各栏按费用包含的不同颜色分别统计，一张雪月费用卡会同时计入雪、月；无五色费用（包括费用 0）归他，所以六项合计可以超过卡组总张数。96 套已取得标签的样本逐项验证与此算法一致。本站投稿按卡面属性，已知多属性／无色归他。

标签校验要求六项完整、非负整数、各项不超过当前卡组张数，合计在卡组张数至五倍张数之间；本地费用资料完整时还要逐项匹配，防止官网列表与旧快照不一致。不再用合计等于卡组张数来判断标签或统计完整性。官网标签缺失时，其本地计算也使用费用颜色统计。

已有官网卡组暂未取得标签时先由本地卡库计算；每日同步在读取列表时也更新已收录卡组标签，即使其详情因最近同步而暂时跳过。用户投稿缺属性资料／官网来源缺费用资料时不猜测数量，属性筛选不会把这些卡组误当作 0 张。官网玩家、赛事分别分页并保存各自游标，避免混合列表在相同日期边界重复；`--pages` 仍限制每次列表请求总量。

2026-10-03 预览库补查：105 套官网卡组中，103 套已取得并校验官网原标签（恢复 4 套重叠费用标签，补回 7 套大阪赛标签）。剩余 `jKIlqu` 的详情显示「デッキ情報を取得できませんでした。」；`R2ZY23` 的详情仍存在，但未出现在作者完整的公开列表中，官网未说明原因。这两套保留本地费用统计，不推断其公开状态或伪造官网标签。

同步每轮优先刷新两种来源首页，剩余列表预算在待处理详情不足时续扫各自旧页；`--pages=1` 时跨轮交替来源。旧混合页码从两来源首页重新开始，保留已有待处理和失败重试队列。

## 维护与发布

新增迁移 `005_publication_compositions.sql`，表 `toolbox_publication_compositions` 存放发布记录对应的类型、会社资格、属性张数、统计来源和所用快照。发布／编辑／官网同步在事务中同步维护；公开数量统计与分页使用同一 SQL，隐藏记录不会计入公开总量。

执行迁移后补建索引，默认只读评估。只有显式 `--apply` 且连接主机等于 `--expect-host` 才写入，以免混淆环境：

```powershell
# 使用已确认环境的 direct DATABASE_URL_UNPOOLED
npm run db:migrate
node scripts/backfill-deck-compositions.js --env-file .env
node scripts/backfill-deck-compositions.js --env-file .env --expect-host "已确认的direct主机" --apply
```

可用 `--official-list PATH` 提供已有官网列表 HTML，只更新与已存卡组费用统计相符的标签。脚本不爬取详情、不创建发布记录、不修改卡组快照。生产升级时先核对生产 direct 连接、执行迁移并补建索引，再部署新代码；不能以预览库的执行记录代替生产升级检查。
